## 1. 系统架构概述

## 2. 分层设计

### 2.1 接入层 (Access Layer)

接入层负责与终端用户交互，支持多种客户端接入方式：

| 客户端 | 技术方案 | 说明 |
|--------|----------|------|
| Web 端 | Next.js 14 + TypeScript | 主站前端，SSR 渲染 |
| 移动端 | Flutter (开发中) | iOS/Android 原生体验 |
| 管理后台 | React + Ant Design Pro | 运营管理界面 |
| 第三方 API | RESTful API / gRPC | 开放平台接口 |

### 2.2 API 网关层

API 网关作为系统的统一入口，承担以下职责：

- **路由转发**：根据请求路径将请求分发至对应的微服务。
- **认证鉴权**：统一处理 JWT Token 验证与 OAuth 2.0 授权。
- **限流熔断**：基于令牌桶算法实现接口级限流，防止雪崩效应。
- **负载均衡**：支持服务实例的动态发现与请求分发。
- **访问日志**：统一记录所有 API 请求的访问日志。
- **跨域处理**：统一配置 CORS 策略。

### 2.3 应用服务层 (Application Layer)

应用服务层采用微服务架构，每个服务独立部署、独立扩展。

#### 核心服务列表

| 服务名称 | 职责描述 | 数据库表 |
|----------|----------|----------|
| **用户服务 (User Service)** | 用户注册/登录、个人信息管理、角色权限管理 | `users`, `roles`, `permissions` |
| **课程服务 (Course Service)** | 课程 CRUD、章节管理、课程分类、资源管理 | `courses`, `chapters`, `lessons`, `resources` |
| **学习服务 (Learning Service)** | 学习进度追踪、学习路径管理、学习记录 | `enrollments`, `learning_progress`, `learning_paths` |
| **评估服务 (Assessment Service)** | 试题管理、考试安排、自动评分、成绩管理 | `quizzes`, `questions`, `exam_results` |
| **订单服务 (Order Service)** | 课程购买、支付对接、订单管理、退款处理 | `orders`, `payments`, `refunds` |
| **通知服务 (Notification Service)** | 站内信、邮件、推送通知、消息模板 | `notifications`, `templates` |
| **内容服务 (Content Service)** | 视频转码、文档处理、内容审核、CDN 分发 | `media_files`, `transcode_tasks` |
| **分析服务 (Analytics Service)** | 数据采集、学习分析、报表生成、数据看板 | `analytics_events`, `reports` |
| **搜索服务 (Search Service)** | 全文搜索、课程推荐、搜索联想、索引管理 | 基于 Elasticsearch 索引 |

#### 服务间通信

- **同步通信**：服务间通过 RESTful API 或 gRPC 进行同步调用。
- **异步通信**：通过 RabbitMQ 消息队列实现事件驱动的异步通信。

### 2.4 AI 智能体层 (AI Agent Layer)

AI 智能体层是 EduFlow 畅学的核心特色，通过 AI 编排引擎协调四个专用智能体协作完成任务。

详见 [AI 智能体文档](ai-agents.md)。

### 2.5 基础设施层 (Infrastructure Layer)

基础设施层提供底层支撑能力，包含：

- **数据存储**：PostgreSQL 主数据库、Redis 缓存、Milvus 向量数据库、对象存储服务。
- **消息队列**：RabbitMQ 用于服务间异步通信和任务调度。
- **监控与日志**：Prometheus + Grafana 监控体系、ELK 日志收集分析。
- **容器编排**：Docker 容器化部署，Kubernetes 生产环境管理。

## 3. 数据流设计

### 3.1 用户学习流程

```
用户登录 → 能力评估 → 路径规划 → 课程学习 → 课后测评 → 智能批改 → 分析报告
               │           │           │          │         │          │
               │           │           │          │         │          │
               ▼           ▼           ▼          ▼         ▼          ▼
           评估服务    学习路径    学习服务    评估服务   作业批改   学习分析
                      智能体                           智能体     智能体
```

### 3.2 智能问答数据流

```
用户提问
    │
    ▼

    │
    ▼
智能问答服务
    │
    ├──▶ 问题分类 (意图识别)
    │
    ├──▶ 知识检索 (Milvus 向量检索 + 全文检索)
    │       │
    │       ▼
    │   课程知识库 / 通用知识库
    │
    ├──▶ 上下文组装 (历史对话 + 检索结果)
    │
    ├──▶ LLM 推理 (GPT-4o / 文心一言)
    │       │
    │       ▼
    │   生成回答
    │
    └──▶ 回答过滤与格式化
         │
         ▼
      返回用户
```

```
    ▼

    ├──▶ 客观题 (选择题/填空题) → 自动比对答案
    │

            │
```

```
    │
    ├──▶ 前端埋点 (页面访问、点击事件、视频播放)

         │
         ├──▶ 学习行为分析

         ▼
```

## 5. 关键技术决策

| 决策 | 选择 | 理由 |
|------|------|------|
| 微服务架构 | 单体服务 vs 微服务 | 支持独立部署、独立扩展，有利于团队并行开发 |
| API 通信 | RESTful + gRPC | RESTful 适用于外部接口，gRPC 适用于内部服务间高性能通信 |
| 异步通信 | RabbitMQ | 成熟稳定，支持消息持久化、死信队列、灵活的路由策略 |
| 向量数据库 | Milvus | 高性能向量检索，支持十亿级规模，适合知识库场景 |
| 智能体编排 | LangChain | 生态丰富，支持多模型切换、工具调用、记忆管理 |

## 6. 可扩展性设计

- **水平扩展**：所有微服务均为无状态设计，支持通过 Kubernetes HPA 进行自动水平扩展。
- **读写分离**：数据库采用主从架构，读操作分发到从库，写操作在主库完成。
- **缓存策略**：多级缓存体系（本地缓存 + Redis 分布式缓存 + CDN 缓存）。
- **分片策略**：用户表和课程表按用户 ID 和课程 ID 进行哈希分片。
- **异步化**：耗时操作（视频转码、AI 推理、批量通知）通过消息队列异步处理。

## 7. 安全设计

- **传输安全**：全链路 HTTPS 加密，API 网关统一管理 SSL 证书。
- **认证授权**：JWT + OAuth 2.0 双认证机制，RBAC 基于角色的权限控制。
- **数据安全**：敏感数据加密存储（AES-256），数据库访问权限最小化。
- **防攻击**：API 限流、IP 白名单、SQL 注入防护、XSS 防护。
- **审计日志**：所有关键操作记录审计日志，支持追溯查询。
